Same harness and scenarios as `../baseline-aa` (`bench.py run`, BASE_TREE = pristine v11.0.0 checkout, inputs always
generated by the V11 tree, paired per seed with alternating order, one discarded warm-up per config per scenario).
Files: `e2e.jsonl` (measured rows with both commits per row), `warmup.jsonl`, `e2e-summary.json`, `summary.txt`,

Output and outcome identical to v11.0.0 on all 63 measured rows (false successes 0). Peak RSS ratio (process tree)
up to 1.354 on decode scenarios. w4/w1 scaling: v11 2.84, v12 3.15 (the V12 w1 is slower, not the w4 faster).

So the merged V12 work at 00bd160 (parallel pass 2 + shift-tolerant orientation) is a net slowdown: T1, T2, T3 and T5
are NOT met at this commit. The orientation scan (5 shifts × 2 orientations of numpy gathers) costs more than the
retry work it saves, and the parallel pass 2 adds overhead that the clean and substitution scenarios (no consensus
work to parallelise) pay in full. Follow-up measurements are in the state notes and later bench directories.
