# Engineering environment

The environment around the VNX-DNA library: how work is decided (LAYA), executed (harness), contained (governor),
assisted (models), queued, observed and gated. It lives in two places:

* **Repository** (`ops/`, `config/`, `experiments/`, `benchmarks/`, `release/`, `docs/releases/`): code and policy,
  identical on every machine. `src/vnxdna` never imports `ops/vnxops`.
* **Machine state** (`/opt/vnx-dna`, override with `VNXDNA_HOME`): measurements, logs, records, backups.

```
 request ──► LAYA (config/laya/*.yaml) ──► harness ──► governor ──► vnxdna.slice scope
   │          classify/plan/select/check      │           admit        (CPU/RAM/swap/tasks caps)
   │          approve/review/accept           │             │
   │                                          ├─ tool:  pytest, ruff, gitleaks, benchmarks (tier 0)
   │                                          ├─ model: Ollama (tier 1–2) / external agent CLI (tier 3–4), text only
   │                                          └─ agent: external agent CLI in /opt/vnx-dna/workspaces/<id> (experiment/<id>)
   ▼
 artifacts/laya/<date>/decision-<id>.json   artifacts/harness/<date>/<task>/record.json   logs/governor.jsonl
```

## LAYA

`REQUEST → CLASSIFY → PLAN → SELECT AGENT → SELECT MODEL → CHECK RESOURCES → APPROVAL → EXECUTE → TEST → BENCHMARK →
REVIEW → ACCEPT/REJECT → LOG` (`ops/vnxops/laya.py`).

* **Classify**: regex rules in `policy.yaml` (first match); otherwise a tier-1 model picks from the declared task types
  (an invalid answer falls back to `implementation`).
* **Plan**: task kind `tool` (test_run, benchmark_run, lint_fix), `model` (log_summary, classification) or `agent`;
  gates from the task's requirements (`pytest_fast` + `ruff`, `bench_smoke`).
* **Approval**: risk `high` and `critical` need `vnxdna laya approve <id>`; approvals are single-use and expire after 72 h.
  Format-surface changes escalate after review.
* **Review**: diff size ≤ 1500 lines, no forbidden paths, secret scan of added lines, docs and tests changed with `src/`,
  evidence labels for research, every gate passed.

| Status | Meaning |
|---|---|
| `accepted` | all gates passed, no human review required |
| `accepted_pending_human_review` | gates passed; branch/output waits for a human |
| `rejected` | review failed (reasons recorded) |
| `failed` | execution failed (failure class recorded) |
| `deferred` | resources or model unavailable now |
| `pending_approval` | waiting for `vnxdna laya approve`, or remote budget exhausted |
| `planned` | dry run (`vnxdna laya plan`) |

## Harness

Each execution writes `record.json` with: task_id, timestamp, decision_id, agent, task_type, kind, model, repository
(path, branch, commit, dirty files, describe), input, attempts (strategy, model, steps, failure), tools_used, tests,
benchmark, result, failure_class, failure_reason, artifacts, workspace/branch for agents, finished_at.

Failure classes: `timeout`, `resource_refused`, `killed_limit`, `model_error`, `tool_error`, `test_failure`,
`policy_violation`, `approval_required`, `secret_detected`, `transient`, `internal`. Only `timeout`,
`resource_refused`, `model_error`, `transient` are retried, at most 3 attempts, each with a different strategy
(`escalate_model`, then `reduce_parallelism`); the same strategy is never used twice. Logs, workspace and traceback are
kept.

## Resource governor

* `vnxdna.slice` (`/etc/systemd/system/`): CPUQuota, MemoryHigh, MemoryMax, MemorySwapMax, TasksMax from
  `hardware-capability.yaml` (`SAFE_CPU_THREADS`, `SAFE_RAM_HIGH`, `SAFE_RAM_LIMIT`, `SAFE_SWAP_LIMIT`, `MAX_PROCESSES`),
  CPUWeight/IOWeight 50 (production keeps 100).
* Each governed job is a transient scope with its own MemoryMax (2 × estimate, ≥ 512 MiB), MemoryHigh 0.9 × that and
  swap cap MemoryMax/8.
* **Admission**: MemAvailable − estimate must stay above `MIN_FREE_RAM`; disk above `DISK_FREE_FLOOR`; class below its
  concurrency limit × level factor. Otherwise wait up to 600 s, then exit 75.
* **Watchdog** (`vnxdna-governor.service`, every 5 s, PSI + meminfo + disk):

| Level | Triggers (any) | Actions |
|---|---|---|
| ELEVATED | MemAvailable < 1.5 × floor, PSI memory some > 10, PSI cpu some > 60, disk < floor | concurrency × 0.5 |
| DANGER | MemAvailable < floor, swap > limit, PSI memory some > 30 | freeze non-essential jobs (cgroup freeze keeps state), unload LAYA-loaded models, concurrency 0 |
| CRITICAL | MemAvailable < 0.5 × floor, swap > 2 × limit, PSI memory full > 25, disk < 0.5 × floor | kill non-essential, freeze essential, unload models |
| OK | none | thaw all, full concurrency |

Escalation is immediate; stepping down needs 3 calm intervals per level. Events go to `logs/governor.jsonl`.
Rollback: `/opt/vnx-dna/rollback/governor-uninstall.sh`.

### Production co-tenancy

This VPS also runs VNX Weather production (`vnxw-prod-*` containers) and an Android test container (`redroid13`).
The governor only acts on units inside `vnxdna.slice`; `resources.yaml` → `protected` lists services it never touches.
The RAM reserve (`prod_reserve_bytes`) is subtracted before VNX-DNA limits are derived, and two CPUs are left free.

## Models

| Tier | Model(s) | Use |
|---|---|---|
| 0 | deterministic tools | tests, lint, benchmarks, release gates |
| 1 | `qwen2.5-coder:1.5b` (Ollama) | classification, small transforms, log summaries |
| 2 | `huihui_ai/qwen3-coder-abliterated` (Ollama, untrusted) | test-generation proposals when RAM allows; exclusive |
| 3 | external agent CLI (`<agent.cli> -p`, set in system.yaml) | implementation, debugging, architecture, review |
| 4 | external agent CLI with web tools | research |

Selection (`models.select`) is deterministic: the cheapest model meeting the task's `min_tier`/`min_quality`
(`models.yaml` → `task_requirements`) that is installed, passed its measured coding benchmark (tier ≥ 2 needs ≥ 3/5),
and fits RAM above the floor; otherwise escalate. One local model loaded at a time. Measurements:
`/opt/vnx-dna/reports/model-benchmarks.{json,md}` (`vnxdna models bench`).

## Queue

`QueueBackend` with `LocalQueue` (SQLite, default, visibility timeout, dead-letter after 3 deliveries), `RedisQueue`
(local redis-server, DB 7, prefix `vnxdna:q`, reliable LMOVE pattern, no client dependency) and `SQSQueue` (optional;
needs boto3 + AWS credentials; only with `queue.sqs.enabled`). An unreachable Redis falls back to local. The system
runs completely locally.

## Observability

`vnxdna status` (CPU, RAM, swap, disk, Ollama, LAYA, harness, governor, MCP, queue, git, last test/build gate) and
`vnxdna doctor [--deep]` (configuration, toolchain, venv, governor, floors, LAYA cross-references, models, MCP, queues,
repository, baseline, backups, permissions; `--deep` adds compileall, ops tests, e2e, benchmark smoke). Both accept `--json`.
