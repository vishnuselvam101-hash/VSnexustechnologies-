# V13 end-to-end benchmark report: V12 (build/v12 6bf7749) vs V13 (build/v13-final)

SIMULATED: every input is produced by the VNX-DNA channel simulator; no DNA was synthesised, stored or sequenced.
One host, one channel family; the numbers are this host's, not a product claim. Committed runs:
`experiments/v13/bench/baseline-aa` (A/A noise band, 6bf7749 against itself), `experiments/v13/bench/ab-final2` (the
A/B run of this report, final engine f7586b9), `experiments/v13/bench/ab-final` (the same run on the pre-fix engine of
a798d89, kept as a record), `experiments/v13/bench/single-runs-0093376` and `single-runs-f7586b9` (single decodes with
the engine counters) and `experiments/v13/bench/stream-volume` (disk-style rates of the streaming codec and the volume). Each
bench directory holds its `e2e.jsonl`/JSON output, `summary.txt`, `run.log`, `operator-notes.txt` and a README.

## 1. Method

`experiments/v13/bench/bench.py run` (the V12 harness with labels `v12`/`v13`, docs/V13_PLAN.md §2): inputs are
generated by the baseline tree (`datagen` random bytes → archive → strands → simulated reads), both trees decode the
same files, paired per seed with the configuration order reversed on odd seeds, one discarded warm-up per configuration
per scenario, n = 5 seeds (3 for 16 MiB). Ratio = v12 seconds / v13 seconds (> 1 means V13 faster), percentile
bootstrap CI of the median ratio (10 000 resamples; at n = 5 it is the min–max range). Peak process-tree RSS is sampled
by the harness every 0.5 s. `compare_aa.py` calls a scenario "beyond noise" only when its CI does not overlap the A/A
CI of the same scenario (`baseline-aa`, both labels at 6bf7749). Outputs are compared by SHA-256 against the input
archive; a false success is a SUCCESS with a different output (0 occurred). A tier is reached only when the CI lower
bound clears it and the scenario is faster beyond noise: **Tier 1 ≥ 2×, Tier 2 ≥ 5×, Tier 3 ≥ 10×**, per workload and
worker count. Component ratios are never reported as end-to-end.

Scenarios: 4 MiB indel decode (substitution 1 %, insertion 0.2 %, deletion 0.2 %, coverage 5) at 1/2/4/8 workers;
the same with 50 % reverse-complemented reads and with 5 % strand dropout (4 workers); clean coverage 3; substitution
2 % coverage 5; 64 KiB indel (1 worker); 16 MiB indel (4 workers); encode 1 MiB and 4 MiB at 1 and 4 workers.

## 2. Environment

4C/8T Linux host (Xeon Gold 6240, kernel 6.8.0-146, Python 3.12.3; `e2e-summary.json` `host`), all native kernels built
in both trees (`python -m vnxdna.native`: every kernel native; V13 adds the `engine` library, the in-place release
build of f7586b9, `stale_libraries` empty on every row). The runs took place in the lab's memory-limited systemd
scope (MemoryMax 8 GiB, no CPU quota) with nothing else scheduled; load at the start of each row is in the rows
(`load1_start`). The A/B run of this report (`ab-final2`) ran all 13 scenarios on 2026-10-18 at f7586b9, the final
code (the commits after it change docs and benchmark evidence only). V13 decodes took the engine rung `stream` on
every row (no fallback). An earlier run at a798d89 (`ab-final`) measured an engine that could skip a distinct strand
sharing a payload window with a verified one; that defect was fixed in f7586b9 and the run is kept as a record.

**The 10× target (Tier 3) is not reached on any workload; neither is Tier 2 (5×).** Tier 1 (≥ 2×) is reached on
two workloads: the single-worker 4 MiB indel decode (2.89×) and the clean decode at 4 workers (2.20×). The 2-worker
indel decode misses it by its lower bound (2.11× [1.99, 2.31]); the other decodes are 1.37–1.76× faster; the encoder
is unchanged (no encode work was in scope beyond the streaming layer, which uses the same encoder).

The pre-fix engine (`ab-final`, a798d89) measured 5.23× [4.72, 5.25] at indel-w1 and 2.2–3.9× on the other indel
workloads. That speed came in part from an unsafe skip: a read was counted as a copy of a verified strand on a
shared 24-nt payload window alone, and a claim that verified one strand closed for every member, including members
that read another address. Random-data benchmarks hide it (the outer code recovered the rare lost symbol and the
output stayed identical), structured data makes it systematic (zero runs, column parity). The corrected scheduler
(§3.1) attempts every copy whose raw header does not name a verified address, which on a 1 % substitution channel
is about a third of the copies; that is the whole difference between the two runs (clean decodes are unchanged).

Scaling versus 1 worker: v12 1.77 / 2.81 / 3.38 at w2 / w4 / w8, v13 1.34 / 1.68 / 1.64. V13's pass 1 scales inside the
engine's thread pool, but the serial remainder (layout probe, pass-1 grouping, pass 2, verification) is a large share
of the wall time at 4 and 8 workers, so the ratio over V12 falls as V12 gains from its worker processes. V13's decode
RSS is ~100 MiB at every worker count (one process, memory-mapped input released as it is consumed) where V12's
grows by ~80 MiB per worker process.

### 3.1 Stage budget (why 10× was not reached; `experiments/v13/bench/single-runs-f7586b9` and `-0093376`, SIMULATED)

Single decodes of the w1 indel fixture (seed 95500) at the final engine f7586b9: 3.047 s = pass 1 2.689 (engine:
scan 0.10, prep (orientation, header keys, fingerprints) 0.31, attempts 2.20 = cheap paths 1.06 + full DP 0.75 +
grouping 0.21, spill 0.06) + pass 2 0.23 + verify 0.01 + ~0.12 of probe and bookkeeping; the V13 Python path
(`engine=v13`) 4.705 s; V12 8.9 s (bench median). The scheduler attempted 323,312 of 655,755 reads (361,152 cheap
attempts, 66,458 full DP attempts) and skipped 332,443 as corroborated copies. The pre-fix engine at 0093376 took
1.748 s with 149,340 attempts (171,182 cheap, 11,722 full) and 506,415 skips: the full DP attempts are where the
corrected rule costs (0.75 s vs 0.16 s), since the copies it now attempts are mostly reads with an indel before or in
the header, which the cheap paths cannot verify. At w4 (seed 95300): 1.681 s = pass 1 1.30 (attempts 1.00 = cheap
0.32 + full 0.29 + grouping 0.20, prep 0.11, scan 0.10) + pass 2 0.25.

The 10× line for the w1 fixture is 0.89 s. The serial items alone (prep 0.31 + grouping 0.21 + pass 2 0.23 +
probe/overhead ~0.12 = ~0.87 s) leave no room for any attempt, so Tier 3 needs structural levers, not tuning: a
native pass 2 and layout probe, the grouping inside the thread pool, a cheaper prep pass, and a scheduler that can
tell a noisy copy from a neighbouring strand without the DP (a header check that survives an indel, e.g. a
header-only parity in a future frame version, or the marker-anchored projection run before the skip decision). At
w4 the same arithmetic applies with V12 at 3.17 s: 10× = 0.32 s, below V13's serial remainder.

## 4. Streaming codec and volume: disk-style rates (`experiments/v13/bench/stream-volume`, SIMULATED)

`stream_volume_bench.py --sizes 4,16 --reps 3` at 6117262 (median of 3, 1 MiB extents, random bytes, every kernel and
the engine native; `stream-volume.json`). These are software codec rates on this host with strands as files, never
physical DNA throughput. "Pool" = the stream's strands shuffled into one SIMULATED read pool (coverage 3, 1 %
substitutions) decoded by archive ID; "range" = each extent decoded from its byte range of the encoder's strand file.

| metric | 4 MiB, 1 worker | 4 MiB, 4 workers | 16 MiB, 1 worker | 16 MiB, 4 workers |
|---|---|---|---|---|
| stream encode (file → strands) | 2.86 MB/s (1.47 s) | 7.65 MB/s (0.55 s) | 2.60 MB/s (6.45 s) | 9.16 MB/s (1.83 s) |
| stream decode by range | 3.37 MB/s (1.25 s) | 4.08 MB/s (1.03 s) | 3.54 MB/s (4.74 s) | 3.71 MB/s (4.53 s) |
| stream decode from a pool by archive ID | 0.69 MB/s (6.06 s) | 0.91 MB/s (4.63 s) | 0.17 MB/s (98.1 s) | 0.38 MB/s (44.7 s) |
| volume write + flush (sequential) | 3.08 MB/s (1.36 s) | — | 3.15 MB/s (5.32 s) | — |
| volume sequential read, cold (fresh open) | 4.20 MB/s (1.00 s) | — | 4.27 MB/s (3.93 s) | — |
| volume sequential read, hot (cache) | 1.75 GB/s (2.4 ms) | — | 1.57 GB/s (10.7 ms) | — |
| volume 4 KiB random read, cold, median / p95 | 246 / 265 ms | — | 249 / 267 ms | — |
| volume 4 KiB random read, hot, median / p95 | 0.014 / 0.016 ms | — | 0.024 / 0.028 ms | — |

Peak RSS of the bench process tree: 67 MiB (encode), 116–172 MiB (stream decode), 172–181 MiB (volume and the 16 MiB
runs, the process grows once and keeps the extent cache). A cold random read costs one extent decode (~250 ms for a
1 MiB extent, the decoder's fixed cost dominates), a hot one is a cache lookup. Encode scales with workers (extents
in flight); decode by range barely does, because each 1 MiB extent is decoded in turn and the per-extent fixed cost
(layout probe, pass 2, verification) is serial.

**Known limitation (pool decode).** Decoding a stream from one shuffled pool runs a whole-pool decode once per extent
(each decode scans every read and keeps its own archive's), so the cost is O(extents × pool size): 6.1 s for 4
extents, 98 s for 16 (1 worker). The range path and the volume, which keeps one strand file per extent, are linear.
The fix is a single partition pass of the pool by archive tag before the per-extent decodes; it is not in V13 (see
the completion report's "Next").

## 5. Reproduction

```bash
# pristine build/v12 checkout 6bf7749 at /root/vnx-dna-lab/v13-base, a second one at v13-base2 (A/A); kernels and the
# engine built in the trees (python -m vnxdna.native; python -m vnxdna.native.engine build)
BASE_TREE=/path/to/6bf7749 VNX_BENCH_OUT=experiments/v13/bench/<dir>/e2e.jsonl PYTHONPATH=src \
  python experiments/v13/bench/bench.py run
VNX_BENCH_OUT=experiments/v13/bench/<dir>/e2e.jsonl PYTHONPATH=src python experiments/v13/bench/bench.py summary
BASE_TREE=... AA_TREE=/path/to/second-6bf7749 VNX_BENCH_OUT=experiments/v13/bench/baseline-aa/e2e.jsonl \
  PYTHONPATH=src python experiments/v13/bench/aa.py run
PYTHONPATH=src python experiments/v13/bench/compare_aa.py experiments/v13/bench/<dir>/e2e-summary.json \
  experiments/v13/bench/baseline-aa/e2e-summary.json
PYTHONPATH=src python experiments/v13/bench/stream_volume_bench.py --sizes 4,16 --reps 3
```
