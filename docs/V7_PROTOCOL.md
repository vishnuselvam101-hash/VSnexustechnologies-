# VNX-DNA V7 experimental protocol

- Status: **PROTOCOL, V7 Phase 0, 2026-10-05.** Normative for every V7 experiment. Where it differs from
  [V7_ARCHITECTURE.md](V7_ARCHITECTURE.md) §4 or §9, this document wins. Threshold *values* marked "proposed" are frozen
  by the per-experiment PREREG commit (section 7); the *rules* in this document are frozen now.
- Inputs: [V7_ARCHITECTURE.md](V7_ARCHITECTURE.md), [research/V7_CHANNEL_FITTING_PLAN.md](research/V7_CHANNEL_FITTING_PLAN.md),
  [research/V7_NANOPORE_DECODING_RESEARCH.md](research/V7_NANOPORE_DECODING_RESEARCH.md), [V6_DEFERRED.md](V6_DEFERRED.md).
- Base: `build/v7-sprint` from v6.0.0 (16b5811). No DNA has been synthesised, stored or sequenced by VNX-DNA.

## 1. Objective and success condition

V7 succeeds if VNX-DNA shows a statistically and reproducibly meaningful improvement over the **V6 nanopore-like
baseline** on **held-out, independently generated** conditions, **without increasing false SUCCESS** (section 6).

The V6 baseline is historical and is not re-stated: `nanopore-like`, v4-balanced, default decoder, **0/20 exact at
coverage 3, 5 and 10** (`experiments/v6/align-band/README.md`, AB-EXP-01; SIMULATED). Every V7 confirmatory run also
re-runs the 6.0 `default` arm on the same seeds, so the comparison is paired; if the re-run differs from 0/20 on the
unfitted model, that is reported as a reproducibility finding, not used to move the baseline.

If V7 does not meet the condition, the completion report says so and the problem moves to V8.

## 2. Evidence classes

Every number in a V7 document or results file carries exactly one class.

| Class | Meaning |
|---|---|
| VERIFIED | Checked by a committed test or script that runs in CI or `vnx-task verify` |
| SIMULATED | VNX strands sent through a software channel model (fitted or not); the model's fit status is quoted with it |
| SYNTHETIC | Inputs generated by software without a channel model (e.g. random strands, mutated reads for fuzzing, toy pools) |
| PUBLIC-DATA-DERIVED | Computed from public sequencing reads (statistics, fitted parameters, consensus on real reads) |
| EXPERIMENTAL | Exploratory runs (A0 and similar) on development data and disjoint seeds; never quoted as a result of V7 |
| PHYSICAL | Real DNA handled by VNX-DNA. **Nothing in V7 is PHYSICAL** |
| THEORETICAL | Arithmetic, specification or a published number not reproduced here |

A fitted model is evidence about a public dataset, not about biology in general. "Realistic" is not used for a model
because it decodes well; a model is described only by its fit metrics (section 5.4) and its source data.

## 3. Datasets and manifest

The manifest `experiments/v7/datasets/MANIFEST.json` (with a stdlib-only script that recomputes it from the data
directory) records, per dataset and per file: source, URL, name, publication, accession, licence and usage constraints,
download timestamp (UTC), SHA-256, format, read count, read-length distribution, quality availability, coverage
information, platform, library preparation, and raw / basecalled / simulated / processed. Data live under
`/root/vnx-dna-lab/data/`, never in the repository. Files without a licence (dt4dds_notebooks designs, Organick,
Chandak) are never committed; `dt4dds` (GPL-3.0) is run only as an external process.

Datasets in scope for V7 (from the fitting plan, section 4): **D04 CNR** (MIT, ONT, pre-clustered; smoke test and
consensus check), **D03 Zenodo 10943282** (CC BY 4.0, ONT, guppy fast and HAC, pass and fail; the primary nanopore
dataset), **D02 DT4DDS** Twist runs ERR12033806 / ERR12033810 with PhiX ERR12033850 (INSDC, Illumina; Illumina
model and quality calibration). Other datasets need a manifest entry and a reason before they are downloaded.

## 4. Data split: fit / development / held-out

The split is computed by a committed script from the manifest alone. Its output (lists of run IDs and reference IDs
per split, plus their SHA-256) is committed **before** any fitting.

### 4.1 Rule

Amendment 1 (2026-10-05, after the dataset manifest and before any fitting or split computation): the manifest showed
that the D02 runs Aging_0a and 0b share one 12,000-design pool, and that the D03 files `file-0`, `file-1`, `file-2`
use three disjoint reference sets of about 30.6k strands, each repeated across basecaller (accurate, fast), filter
and orientation (forward, backward) groups. The rule below is the amended one; the original held a run out for D02 too,
which would have leaked its references.

1. **Held-out run.** A whole run is held out only where runs have **disjoint** reference sets, so that holding it out
   does not leak references. Index `int(SHA-256("VNX-V7-HELDOUT/" + dataset_id), 16) mod n_runs` over the runs sorted
   by name. For D03 (`dataset_id` = `D03`, runs `file-0`, `file-1`, `file-2`) this is **`file-1`**; every group of that
   file (both basecallers, pass and fail, both orientations) is held out together. D02 (shared designs) and CNR (one
   run) get no held-out run; for them the split is by reference only, and section 4.3 reports it as the weaker kind.
2. **Reference buckets.** Every reference (designed strand) gets `b = int(SHA-256(c), 16) mod 10`, where `c` is its
   canonical sequence: the lexicographically smaller of the sequence and its reverse complement, upper-case ASCII. A
   reference therefore lands in the same bucket in every group, orientation and run.
   - **FIT** = non-held-out runs, buckets 0-5 (60 %).
   - **DEV** = non-held-out runs, buckets 6-7 (20 %).
   - **HELD-OUT** = the held-out run (all buckets) plus buckets 8-9 of every run.
3. A reference in the held-out buckets is held out in every run, so no held-out reference is seen during fitting
   through another run.

### 4.2 Use of each split

| Split | May be used for | Never used for |
|---|---|---|
| FIT | estimating model **F** parameters | validation, decoder development |
| DEV | validating model F (section 5.4), A0 exploration, choosing decoder parameters, writing PREREG thresholds | confirmatory claims |
| HELD-OUT | after the PREREG commit only: (1) one validation of the frozen F (report only); (2) fitting the evaluation model **E** and the transcript-replay channel **R**; (3) confirmatory runs (A-EXP-01 and later) | anything before the PREREG commit; any parameter change after it |

Held-out files are not opened by any script before the PREREG commit except to hash them for the manifest. The split
script refuses to emit held-out read data unless it is given the PREREG commit SHA, and it records each access in
`experiments/v7/datasets/ACCESS_LOG.jsonl` (commit SHA, script, timestamp, purpose).

### 4.3 Independence and its limits

- The held-out run is a separate sequencing run of the same pool, so it is independent in sequencing noise but not in
  synthesis, chemistry or pool design. Results are described as "held-out run and references of dataset X", never as
  independent physical validation.
- D03 files come from one synthesis order and one lab; D02 and CNR are split by reference only, so their held-out
  references share runs (sequencing noise, library) with the fit references. D02 qualities are binned to three values
  (11, 25, 37), which limits any quality calibration (section 9). D03 `file-0` has low coverage (median 3-7 reads per
  cluster) and up to 2,873 empty clusters per group; coverage statistics are reported per file. If a dataset has fewer than
  2,000 references in a split, or if the per-split rates differ by more than 3 bootstrap SE for reasons that are not
  sampling, the completion report states that the split is weak for that dataset.
- VNX strands (313 nt, v4-balanced) are longer than the public references (110-150 nt). Applying a fitted model at
  313 nt uses the relative position profile; this extrapolation is a stated limitation of every SIMULATED-on-fitted
  result.

## 5. Channel-model fitting

The method is the fitting plan's section 3 (edlib global alignment with leftmost indel normalisation, read
assignment by minimiser mapping, estimators of section 3.3, bootstrap over references with 200 resamples), with these
rules.

### 5.1 What is estimated, and its label

| Parameter | D03 (ONT) | D04 CNR | D02 (Illumina) | Label in the model |
|---|---|---|---|---|
| sub / ins / del rates, substitution matrix | yes | yes | yes | measured |
| indel length (deletion runs, insertion runs) | yes | yes | yes | measured |
| homopolymer multipliers | yes | yes | yes | estimated (model selection over min_run) |
| context (k = 3) conditional rates | yes | yes | yes | measured; used only if the schema field exists (5.3) |
| position profile | yes | yes | yes (and by cycle) | estimated (binned) |
| read length, truncation | censored at ±15 nt | biased by clustering | yes | measured with stated censoring |
| quality distribution and calibration | no | no | yes | measured (D02 only); nanopore quality is **assumed** and labelled so |
| dropout | upper bound (empty clusters) | upper bound | yes | inferred |
| coverage distribution | yes | yes | yes | estimated (Poisson, NB, Poisson-lognormal; AIC) |
| orientation (reverse-complement share) | yes | no (pre-oriented) | yes | measured |
| error correlation (P(event at i+1 \| event at i)) | yes | yes | yes | measured; reported as misfit if not representable |
| synthesis vs sequencing split | no | no | yes (PhiX) | inferred |

I.i.d. errors are not assumed: if correlation, context or insertion-run statistics differ from the fitted
independent model beyond the M-thresholds in 5.4, the model either represents them (5.3) or is labelled with the
misfit.

### 5.2 Models produced

- **F** (per dataset and condition): fitted on FIT. Used for development and for A0.
- **E** (per dataset and condition): the same fitter, run once on HELD-OUT after the PREREG commit. Used only for
  confirmatory evaluation. E is never inspected for tuning; its parameters are reported next to F's.
- **R** (transcript replay, D03 and CNR): edit transcripts of HELD-OUT reads replayed onto VNX strands of the same
  length class (SIMULATED, replay of PUBLIC-DATA-DERIVED transcripts). It carries measured error positions and
  correlations without a parametric model. Built after the PREREG commit.

### 5.3 Model format `vnx.channel-model/2`

`/2` extends `/1`; every `/1` model stays valid and loads unchanged (a test asserts this for all 14 shipped models).
`/2` adds:

- `model_id`; `provenance`: datasets (ID, URL, SHA-256 of every file used), split (`FIT`/`HELDOUT`) and the split
  manifest SHA-256, fitting method and version, fitting commit SHA and dirty flag, random seed, timestamp (UTC),
  software versions;
- per parameter: `value`, `ci95` (bootstrap) and `basis` (`measured` / `estimated` / `inferred` / `assumed` / `synthetic`);
- optional opt-in fields for effects `/1` cannot express: k-mer context rates, insertion-run lengths, error
  correlation, forward/backward asymmetry. A `/1` reader ignores none of these silently: loading a `/2` model with
  such fields through a `/1`-only path is refused with an error.

The parser is size- and depth-limited and fuzzed (directive §21, §22).

### 5.4 Validation before use

Model F is validated against **DEV** with the fitting plan's metrics M1-M10 (section 3.4 of the plan, thresholds as
stated there). A model that fails M2, M3 or M8 is labelled **INADEQUATE** in its JSON and in V7_CHANNEL_MODELS.md and
is not used to choose decoder parameters. It may still be run, labelled, as a stress condition. The once-only
validation of frozen F against HELD-OUT after the PREREG commit is reported, never acted on.

## 6. Outcomes and false SUCCESS

Each decode is classified by comparing the decoder's claim with ground truth (the original input bytes, SHA-256).

| Outcome | Definition |
|---|---|
| EXACT | status SUCCESS, exit 0, output SHA-256 equal to the input |
| **FALSE SUCCESS** | the decoder publishes bytes as correct (status SUCCESS, exit 0, a `--select` result, or any byte range reported as verified in a PARTIAL report) and any of those bytes differ from the input |
| PARTIAL | status PARTIAL; every byte reported as verified is correct; the share of verified bytes is recorded |
| EXPLICIT FAILURE | status FAILURE or non-zero exit with a typed error, no bytes published as correct |
| CRASH | uncaught exception, signal, sanitizer report or timeout; counted as a failure and filed as a defect |

Rules:
1. FALSE SUCCESS is reported separately in every table, for every arm and cell, and is never folded into "success".
2. Acceptance target: **0 FALSE SUCCESS** across all confirmatory decodes. With N decodes the report gives the 95 %
   upper bound 3/N (rule of three).
3. A single FALSE SUCCESS in any arm that would ship rejects that arm until the cause is fixed and the experiment is
   re-registered with new seeds.
4. The failure stage is recorded for every non-EXACT decode with the taxonomy of section 8.

## 7. Pre-registration

Every confirmatory experiment has a PREREG file committed before its first confirmatory seed runs. It states:
datasets and model SHA-256s (F, and how E and R will be built), seeds, channel parameters, strand length and profile,
coverage levels, dropout, sub/ins/del rates, error severities, arms, metrics, stopping rule, acceptance thresholds,
the false-success definition (section 6) and the decision rule. The run is reproducible from a manifest
(`vnx.experiment/1` plus commit SHA, dataset SHA, seeds, configuration, environment, output hashes, software version,
experiment ID).

Exploration (A0) uses DEV-derived models and seeds 82000-82099 only. Confirmatory seeds start at 82100 and are not run
before their PREREG commit. Changing a threshold after the PREREG commit requires a new PREREG with new seeds, and the
old result is reported too.

## 8. Nanopore decoding: failure taxonomy and acceptance (A)

### 8.1 Taxonomy (instrumented before any algorithm change)

The decoder report gets one counter block per stage, so every non-EXACT decode has a first failing stage:
read parsing (malformed, oversized), orientation, clustering (no cluster, false-positive assignment, split strand,
merged strands), consensus (ambiguous column, insufficient reads), alignment / synchronisation (drift beyond band,
marker loss), indel placement, address (header corrupted, scrambler variant), inner ECC, checksum (CRC-32), coverage
(strand with 0 or 1 reads), outer ECC, superblock, archive (container SHA-256). Phase A starts by running the 6.0
decoder with this instrumentation on the V6 nanopore-like cells and on F, before any new decoder code is written
(experiment A-DIAG).

### 8.2 Header-independent clustering requirements

Missing or corrupted headers, arbitrary read order, reverse-complement reads, corrupted, partial, duplicate and
variable-length reads, and dropout are all handled. Each read assignment carries a score; a read below the
acceptance score is left unassigned and counted, never assigned to the nearest cluster. Cluster frames are fill-only
(FC-9 in the architecture document).

### 8.3 Confirmatory experiment A-EXP-01 (proposed values; frozen by its PREREG)

Arms: `default` (6.0), `cluster` (`--read-clustering fallback`), `smart-auto`, `cluster+smart-auto`,
`retry-band-16`. Profile v4-balanced, 20,000 B; secondary v4-dense and v6-high-dropout.

| Condition | Coverage | Seeds |
|---|---|---|
| `nanopore-like` (unfitted, V6 baseline continuity) | 3, 5, 10, 15 | 20 per cell |
| model **E** (D03 HAC pass, held-out) | 3, 5, 7, 10, 15 | 20 per cell |
| model **E** (D03 fast pass, held-out; harsher) | 5, 10, 15 | 20 per cell |
| replay **R** (D03 HAC pass, held-out transcripts) | 5, 10, 15 | 20 per cell |
| 14 shipped models (no-harm check) | 3, 5, 10 | 20 per cell |
| cell L (uncompressed, zero-filled input) | 10 | 20 |

Primary criteria (proposed):

| ID | Criterion | Rule |
|---|---|---|
| P1 | no FALSE SUCCESS | 0 in every arm and cell |
| P2 | improvement on held-out data (the §1 success condition) | on model E (HAC pass) at coverage 10: `cluster` exact - `default` exact, paired, Newcombe 95 % lower bound > 0.25, and the same sign on replay R at coverage 10 |
| P3 | improvement over the historical baseline | `nanopore-like` coverage 10 and 15 pooled (40 paired seeds): `cluster` ≥ 32/40 exact |
| P4 | no harm | 0 seeds in any cell where only `default` is EXACT |
| P5 | cost where `default` decodes | median time ratio ≤ 1.10; every child VmHWM ratio ≤ 1.20 |
| P6 | determinism and native equivalence | 1 vs 4 workers identical; native = reference on ≥ 100,000 reads |

Decision rule: P1, P4 or P6 REJECT means the arm is not shipped until fixed and re-registered. P2 REJECT means the V7
success condition is not met; the completion report says so and the problem moves to V8, whatever P3 shows. P3 or P5
REJECT means the arm ships opt-in only. Coverage 3 is reported without a claim: at mean coverage 3 under NB(μ, 4),
29 % of strands have at most one read (THEORETICAL, architecture §4).

A0 (EXPERIMENTAL, DEV models, seeds 82000-82099) may change the proposed values before the PREREG commit. If A0
shows that P2's threshold is out of reach even with oracle clusters, the PREREG states a lower threshold with the A0
evidence; it may not drop P1, P4 or the held-out requirement.

## 9. Soft decisions (C)

Job #81 (smart + soft as default) and quality weighting are re-run under this protocol: F for development, E/R and
fresh seeds for confirmation, with a `cluster` arm. The V6 quality-weighting result (213/520 vs 211/520, C2 REJECT;
SIMULATED) stands as the prior; quality weighting is tested on D02-derived calibrated qualities only, because the
nanopore datasets have no qualities (nanopore quality is an assumption and is labelled so). If efficacy is not
significant, it stays opt-in or is removed from the default proposal.

## 10. Default changes

A V7 default change needs all of: an ACCEPT under a PREREG, held-out evaluation, regression tests, a compatibility
review, a time and memory measurement, a security review, a written rationale, and a founder decision. A passing
A-EXP-01 therefore makes `--read-clustering fallback` eligible, not default.

## 11. Decisions on the architecture's open questions (§12)

1. Default clustering budget: 4,000,000 unplaced reads, stop and report (FC-5) when exceeded. Revisit with A-EXP-02.
2. A passing A-EXP-01 does not change the 7.0 default by itself (section 10); the default decision is taken together
   with #81's.
3. Candidate W (address-keyed whitening for frame 6) is adopted only if cell L fails; this rule is fixed now.
