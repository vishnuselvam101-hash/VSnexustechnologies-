## 1. Short answer

1. The two V6 walls are the same two walls the literature reports for nanopore data. The strongest direct evidence is the DNAformer preprint: its index-based binning (the same idea as VNX-DNA's header grouping) clustered 99-100 % of Illumina reads but only 26-33 % of nanopore reads, with a 4.1-5.07 % nanopore error rate (WET-LAB, preprint; section 4.2). VNX-DNA's "exact address in 3.8 % of reads" is the same failure at a higher simulated error level.
2. What works in published pipelines is: (a) cluster reads without trusting an index, using content similarity (hash signatures, q-gram or k-mer filters, tree or alignment based tools such as CD-HIT, MMseqs2, Clover); (b) reconstruct one strand per cluster by alignment-based consensus (BMA with lookahead, iterative, MSA/POA, or trellis/HMM soft combining); (c) only then decode the header and the code. Wet-lab nanopore systems that report full recovery use this shape (CHN, section 5.1) or a code designed for it (section 4).
3. Both walls can be attacked **without a format change**, because the front end (clustering, consensus) sits before the existing frame decoder, and the existing marker template can be used for probabilistic (marker-code style) inference instead of hard erasure. A format change (a frame-6 address that survives indels, or an indel-correcting inner code such as HEDGES) is a second step, not a precondition.
4. Coverage matters. Published reconstruction results degrade sharply for clusters of 4 reads or fewer (DNAformer preprint, section 3.2). VNX-DNA's coverage-3 cells are therefore unlikely to decode on nanopore-like noise whatever is chosen. THEORETICAL for VNX-DNA.
5. No source found reports a pipeline of "outer Cauchy RS over strands + inner RS per strand, no indel-aware inner code" decoding real nanopore reads. VNX-DNA would be testing something not shown in the literature. The nearest wet-lab structure (RS outer code, MSA consensus, no indel-correcting inner code) is CHN, but it also uses a custom composite-letter alphabet and a tree decoder.

### 4.2 Why the VNX-DNA header cannot be rescued in place (THEORETICAL)

- Neighbouring addresses differ in few bits. The scrambler XORs every strand of a given variant with the same keystream (spec invariant I-2), and a XOR preserves the bit-level difference between two plain headers. If the 2-bit-per-nucleotide map is direct, two adjacent symbol or group indices differ in about one or two nucleotides. Matching a corrupted header against a dictionary of expected headers (barcode demultiplexing style) therefore cannot separate neighbours when per-read error is several percent. Published systems solve this with index codewords chosen to be far apart in edit distance: DNAformer uses a pre-computed set of indices at a minimum edit distance (preprint, methods), and Welter et al. compared four index codes, finding a Varshamov-Tenengolts index code best at coverage 5-10 in their simulations (preprint, IN SILICO on wet-lab channel data). Both are format changes.
- Byte 0 (scrambler variant, unscrambled, invariant I-1) is a single point of failure. Without a format change the decoder can try every variant on a clean consensus strand. The cost is a multiple of the number of variants (the count is not stated in this note's sources; take it from `v4/constraints.py`).
- HEDGES attacks the same problem differently: "salt" (the strand ID bits are fed into the hash of the first message bits, so that errors in the ID are corrected as part of the strand decode). Press et al. say a wrongly ordered strand looks to the outer decoder like a full strand of errors, so the ID must be protected. In their blind in-vitro decode, 10-15 % of sequenced strands could not be matched to any input strand even in the control with known sequences (peer-reviewed, Illumina).

## 5. Nanopore wet-lab systems that report end-to-end recovery

### 5.1 CHN (Composite Hedges Nanopores), Nature Communications 2024; bioRxiv 2024.07.12.603190

- Pipeline: MinION R9.4.1, basecalling, read clustering with MMseqs2, MSA with MUSCLE, consensus, tree-search maximum-likelihood decoder with penalty pruning, outer RS(40,36).
- Results as extracted: text file (219 bytes in 7 composite strands) recovered at 4x coverage; image (4,109 bytes in 112 composite strands, equal to 896 normal strands) at 8x; indel rates up to 15.9 % and substitution up to 7.8 % claimed correctable; decode times about 5 min (text) and 75 min (image); sequencing 20 and 120 min; information density 0.59 raised to 1.17 with an eight-letter degenerate alphabet.
- Evidence: WET-LAB, peer-reviewed. The scale is two files of a few kilobytes. The code is MIT; data on Zenodo 10.5281/zenodo.12720799. The way the preprint describes its strand-ID barcodes was extracted by a summarising tool and is ambiguous, so how addresses are handled was not confirmed.
- Fit: it shows clustering by sequence similarity plus MSA works at nanopore error levels for a small pool. It is not evidence for a 313-nt, megabyte-scale archive.

## 6. Compatibility with VNX-DNA's pipeline

Pipeline today: header (variant, version/kind, tag, group, symbol) + payload + CRC-32 + inner RS(r = 16) per strand, markers on a fixed template, hard-decision template alignment with erasure of any segment containing an indel, outer Cauchy RS across strands, V6 product code across stripes.

## 7. Ranked recommendation for V7

All expected-gain statements below are **THEORETICAL for VNX-DNA** unless a published result is named. None has been run on VNX-DNA.

### Rank 1. Header-independent clustering plus alignment-based consensus, in front of the existing frame decoder (no format change)

- Why: it removes wall 1 at its source. The published nanopore failure of index binning (26-33 % of reads clustered, DNAformer preprint, WET-LAB) is the same failure as VNX-DNA's 3.8 % exact address, and the one wet-lab nanopore system without a custom inner code (CHN) clusters by sequence similarity and builds an MSA consensus before decoding.
- Expected gain: THEORETICAL. A consensus of several aligned reads has far fewer indels than any single read, so the header, CRC and inner RS should see mostly substitutions. Published support: reconstruction accuracy on nanopore clusters rises with cluster size up to about 15 reads and is poor at 4 or fewer (DNAformer preprint, WET-LAB, preprint). So expect gains at coverage 10 and above, not at 3. The V6 smart-indel option already turned consensus-limited cells from 0/20 to 20/20 on other high-indel models (SIMULATED, `V6_DEFERRED.md` §3), which suggests the back end responds to cleaner consensus, but nanopore-like failed at the superblock stage in both arms.
- Cost: clustering with a k-mer pre-filter then banded edit-distance verification is sub-quadratic; consensus by POA is SIMD-fast. A pure-Python build is likely too slow; the repository already has a C aligner kernel to extend.
- Check first (TOY result in section 4.1 says feasibility only): measure cluster purity and recall on the existing nanopore-like cells at coverage 5, 10 and 15, before any decode claim.
- Risks: pool size growth raises false pairs; reverse-complement orientation; neighbouring addresses sharing header k-mers (cluster on the payload region); patent P5 (counsel).

### Rank 2. Marker-template soft inference (probabilistic alignment) instead of whole-segment erasure (no format change)

- Why: it targets wall 2. Today any indel inside a 6-byte segment erases the segment (41.3 of 70 bytes erased per aligned read at band 16, SIMULATED). Marker-code and trellis decoders (Davey-MacKay 2001, Trellis BMA 2021, Maarouf 2023, Welter 2024) resynchronise after an indel and output symbol probabilities, so the same marker positions carry information through errors.
- Expected gain: THEORETICAL for VNX-DNA. Published support is for other codes and strand lengths (110-150 nt, marker-repeat inner codes with 4-9 % overhead, Trellis BMA experiments on CNR), and mostly IN SILICO or fitted on wet-lab channel data. Welter et al. report below 1 % frame error for an accurate-basecaller setup at about 4 % error, with a code and decoder designed together; that does not transfer automatically to an RS inner code.
- Cost: highest of the three in engineering time. Trellis BMA was measured at 61.2 h for 10,000 clusters of 16 reads on 32 cores (DNAformer preprint), so a bounded-drift, banded version with per-segment resynchronisation at the existing markers is the realistic target, and its speed is unknown.
- Dependency: Rank 1 (or a clustered public dataset such as CNR, whose reads are already clustered, MIT licence) so that the soft stage can be tested separately from clustering.

### Rank 3. A frame-6 address and header that survive indels (format change, inside the V7 compact-class work)

- Why: even with perfect clustering, a header read from a noisy single read fails; a header designed for it makes clustering a refinement instead of a necessity, and makes low coverage (3-5) less hopeless. It also removes the single point of failure of the unscrambled variant byte.
- What: an address codeword with a minimum edit distance between neighbouring addresses (VT or search-designed index code, as in Welter et al., IN SILICO on wet-lab channel data; and DNAformer's edit-distance-spaced indices), error protection of the address by salt-style hashing (HEDGES, in vitro on Illumina) or repetition at both strand ends (Welter's layout), and a deterministic way to recover the variant (try all, or derive from the superblock).
- Expected gain: THEORETICAL; published numbers are for other layouts. The rate cost is stated by Welter et al. as a trade-off they optimised per coverage; it is not quoted here.
- Why third: it changes the format (frame 6, superblock 3) and should wait for Rank 1 measurements that show how much header protection is still needed once reads are clustered.

Not recommended for V7: neural reconstruction (GPU, training data, index binning dependency), adopting HEDGES or DNA-Aeon wholesale (rate cost: HEDGES needs code rate 0.25 for 7-10 % error against VNX-DNA's about 0.81 bits/nt; both are better used as external comparison points under the B1 benchmark plan), and any raw-signal soft decoding (VNX-DNA has no basecaller-posterior input).

### Suggested measurement plan (for the reviewer to accept or change)

1. Fit the nanopore-like model to public data first (job 19 and the vault decision on the CNR fit), so that "nanopore-like" has an anchor. CNR gives per-read rates (5.77 %), not a 313-nt strand-length profile.
2. Pre-register, per stage: cluster purity and recall, consensus exact rate, header exact rate on consensus, then end-to-end decode. This mirrors the `superblock / outer-address / outer-consensus` funnel already used in P4-EXP-01.
3. Coverage cells 3, 5, 10, 15, 30; pool sizes at least 10x the toy's 400 strands, to expose false pairs.
4. Report CNR consensus accuracy for the new consensus against the published BMA, Iterative and Trellis BMA figures, noting the dataset's known generation flaw.
