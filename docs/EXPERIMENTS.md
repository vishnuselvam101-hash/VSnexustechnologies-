# Experiments and Monte Carlo trials

> **SOFTWARE SIMULATION, not a physical experiment.** Success rates below describe the VNX-DNA decoder under the
> simulated channel of [CHANNEL_MODEL.md](CHANNEL_MODEL.md). They say nothing about synthesised or sequenced DNA.

## The experiment engine

```bash
vnx-dna experiment run \
    --input input.bin --output experiment/ \
    --coverage 10 --substitution-rate 0.001 --insertion-rate 0.0001 --deletion-rate 0.0001 --dropout-rate 0.02 \
    --seed 42 --trials 1000
```

1. The input is stored and encoded once (FASTA strands).
2. Each trial *t* runs the channel with seed `seed + t`, then (by default when coverage > 1) `cluster` →
   `consensus`, then `recover`. The recovered bytes are hashed **outside** the decoder and compared with the input's
   SHA-256.
3. Trials run in parallel processes. Results do not depend on the worker count.
4. Outcomes: `exact`; `failed-detected` (the decoder refused and wrote nothing, with its error category);
   `undetected-corruption` (wrong output presented as success: a bug, always reported); `internal-error` (an
   unexpected exception: a bug, always reported).

Files written, all generated by the program:

| file | content |
|---|---|
| `configuration.json` | input size and SHA-256, store options, channel configuration, seeds, archive ID, strand count, environment (versions, git commit) |
| `results.json` | every trial (seed, outcome, error category, strands, reads, reads per strand, dropped strands, zero-read strands, error counts, coverage histogram, consensus statistics, ECC statistics, runtime, recovered SHA-256) and the summary |
| `results.csv` | one row per trial |
| `summary.txt` | human-readable summary |

The summary reports trials, successful and failed recoveries, detected failures by category, undetected
corruption, internal errors, mean errors, coverage statistics, ECC statistics and runtime, plus the success rate
with a **Wilson 95 % confidence interval**. The Wilson interval stays meaningful at 0 % and 100 %. For example, 1000/1000
successes gives [0.996, 1.000], not a certainty.

## Reproducing

`python research/v2/run_v2_research.py --out research/results/v2` reruns every experiment (about an hour on 8 CPUs), and
`python research/v2/render_v2_tables.py` refreshes the tables. Each result file records the software version, git
commit and machine. Trials use deterministic seeds, so the same code on the same inputs gives the same per-trial
outcomes.

## Statistical honesty

* A success rate is a property of **this decoder under this simulated channel** at the stated parameters. It does
  not transfer to real chemistry, whose error profiles (context-dependent errors, dropout correlated with GC content,
  strand breakage) are not modelled.
* Confidence intervals cover sampling error only, not model error.
* "Undetected corruption: 0" across all trials is evidence that the verification chain works. It is backed by a
  design argument (CRC-32 per strand, then SHA-256 per chunk and per object), not by the trial count alone.
