# Algorithm comparison: DNA-storage coding, indel recovery, consensus and clustering

Status: research note, 2026-10-05. It compares algorithms, not companies. It is not a benchmark. No physical DNA was synthesised or sequenced for this document.

All VNX-DNA results quoted here are SIMULATED (software strands and a software channel) and cite repository files at commit `081697b` (branch `build/v6-p1`), as read by the baseline audit. The package version is still 5.0.0; V6 is unreleased. No claim is made that VNX-DNA is better than, ahead of, or equivalent to any listed algorithm. No benchmark on a shared protocol exists: the status for every VNX-DNA versus external comparison is **not benchmarked**.

Screening versus constrained coding, in terms of the records above: DNA Fountain and VNX-DNA both reject candidates that violate constraints (rejection or scrambler screening); YYC, Wukong, the enumerative code and SPIDER-WEB build the constraint into the mapping. Whether screening costs rate or fails on long strands depends on the constraint: the baseline records that a strict homopolymer limit of 3 over about 300 nt "can make encoding fail" in VNX-DNA (baseline B.1, `docs/LIMITATIONS.md`). Secondary structure, melting temperature and primer design are ABSENT in VNX-DNA (baseline B.1); Storage-D includes primer design with Primer3 and BLAST.

## 5. How VNX-DNA V5/V6 differs from Trellis BMA

Both address reading insertion/deletion/substitution noise from several reads of one strand. They differ in what is assumed, what is inferred and what has been shown.

| Dimension | Trellis BMA (as described in the paper and repository) | VNX-DNA V5/V6 (baseline, commit `081697b`) |
|---|---|---|
| Problem | Coded trace reconstruction: estimate one strand of a known inner code from a cluster of reads | Decode a whole archive: frames, inner RS, outer Cauchy RS, container, from a pool of reads |
| Input | Reads already clustered (the dataset used Rashtchian et al. clustering) | Unclustered reads; grouped by the decoded address in each frame header; orphans (reads whose address cannot be decoded) are counted (31% orphans at the harsh channel, `docs/LIMITATIONS.md`) |
| Channel model inside the decoder | i.i.d. IDS HMM with fitted parameters; a full trellis per trace | Marker template with banded DP; an indel makes the affected segment an erasure; no probabilistic IDS model in the alignment |
| Where the code enters | The code trellis (marker-repeat or convolutional) is combined with the IDS trellis, so code structure helps the alignment | The alignment uses only the marker template; code structure (RS, CRC-32) is applied afterwards on the aligned symbols |
| Combining traces | Single-trace trellises exchange soft information; linear in the number of traces; output is soft symbol posteriors | Consensus with soft posteriors over reads grouped by address; optional bounded local search with consensus realignment for indels (smart indel recovery, V5); optional erasure / GMD-Chase soft decoding |
| Output | Soft posteriors for an outer decoder (the outer code is assumed and not implemented) | Hard symbols with CRC check; erasures to the outer Cauchy RS; V6 adds a product code across stripes |
| Redundancy needed | Inner code rate 100/110 to 104/110 for MR codes in the paper | Marker overhead (3 nt per 24 nt), 8 header bytes per frame, inner RS parity (r=16 default), outer parity (measured redundant-strand overhead 0.249-0.251 in the V6 simulations, `experiments/v6/phase1/summary.md`) |
| Evidence | author-reported, in silico and on real ONT reads of an uncoded pool (level 3 data); figures only | SIMULATED only; no wet-lab or real-sequencing data anywhere in the codebase (baseline B.11) |
| Implementation | Python + numba notebooks, archived, no tests | C11 aligner and RS kernels via ctypes with pure-Python fallbacks, golden tests, differential fuzzing (700k reads for the V5 aligner, baseline A.3), sanitizers |
| Scope of metric | Error rate and achievable information rate versus number of traces | Decode success versus dropout, coverage and burst length; throughput |

What this means, stated carefully:

1. VNX-DNA does not implement joint multi-trace soft inference over a code trellis. Whether adding it would improve decoding on VNX-DNA frames is not known.
2. Trellis BMA does not address archive structure, dropout, outer coding, encryption or random access, and its reported results do not include an outer code.
3. The two have not been run on a shared protocol. TrellisBMA reports on the Microsoft CNR dataset (110-nt strands, 269,709 reads, with the dataset's known generation flaw). VNX-DNA cannot decode that dataset because it decodes only VNX4 frames (baseline B.12). Using it would need a clustered-read consensus interface in VNX-DNA, which does not exist.
4. No VNX-DNA number in this repository bears on Trellis BMA's reported rates. **Not benchmarked.**

## 9. Recommendations

Every item in this section is a **RECOMMENDATION (THEORETICAL until benchmarked)**. None rests on a same-protocol measurement. The order inside each list is not a ranking.

### 9.1 Algorithms worth implementing

| Algorithm | Reason (one line) |
|---|---|
| Enumerative bounded-homopolymer mapper (as an opt-in mapping mode) | An exact rate reference exists (limits 1.9227 / 1.9823 / 1.9957 / 1.9989 bits/base for k=2..5 in the author's slides) and VNX-DNA's screening mapper has no measured rate gap; first step is to measure that gap |
| Clean-room HEDGES-class inner indel code (from the PNAS paper, with an MIT-compatible RS) as a comparison inner code | HEDGES is the only inner code with published wet-lab depth-versus-rate data; VNX-DNA has no indel-correcting code to compare against markers plus RS erasures; licence (Schifra) forbids embedding the reference code |
| Clustered-read consensus interface with BMA/BMALA baseline, then Trellis-BMA-style soft combining | VNX-DNA decodes only addressed VNX frames; a trace-reconstruction mode would allow use of the CNR dataset and a first like-for-like test of consensus quality (with the dataset's flaw reported) |
| Clustering of unaddressed reads (LSH or tree-based, such as Clover's approach, clean-room) | Baseline B.5 and B.12 list unaddressed read clustering as ABSENT, which blocks any third-party dataset and any address-loss analysis |

### 9.2 Algorithms to support or compare only (run as external processes through a harness, no code copied)

| Algorithm | Reason (one line) |
|---|---|
| DNA-Aeon (MIT; AGPL Raptor submodule as a separate process) | Public indel-capable constrained codec with in-vitro tests, already wrapped by two harnesses |
| DNA Fountain and NOREC4DNA Raptor/LT (GPL / AGPL) | Reference fountain codes; copyleft means external process only |
| YYC and Wukong (MIT) | Wet-lab-reported constrained mappers; useful as mapping-level baselines |
| StairLoop, Chandak LDPC and convolutional codes, DBGPS (GPL / MIT) | Soft-decision and assembly approaches that VNX-DNA lacks; compare before deciding to implement |
| Derrick (MIT) | Soft-decision RS with a published in-vitro result, closest to VNX-DNA's opt-in soft decoding |
| Gungnir (BSD-3-Clause) | In-silico single-copy recovery at high error rates; compute-heavy |
| DNAformer and TReconLM (neural) | Need a GPU and training data; datasets "on request" or no licence; evaluate only as an external reference |
| dt4dds channel, via dt4dds-benchmark (GPL-3.0) | The only public channel fitted to real data; run VNX-DNA as an external `encode.sh` / `decode.sh` pair and label results SIMULATED |
| UNACORM (GPL-3.0) and Chamaeleo (MIT) | Cheap multi-codec and mapping-level comparisons; weaker channel models and student re-implementations |

| Algorithm | Reason (one line) |
|---|---|
| Church 1-bit and Goldman rotating code as production mappers | 1.0 and at most 1.585 bits/nt; keep only as density baselines |
| SPIDER-WEB embedding | Custom BGI licence needs BGI's permission for commercialisation; preprint with simulation only; "months on a laptop" runtime claim |

| VT-code work as a stand-alone item | No audited implementation and no benchmark; reconsider only inside a HEDGES-class comparison |

## 10. Limitations of this comparison

- No VNX-DNA result has been compared with an external algorithm on a shared protocol.
- Most performance figures are the authors' own and come from different channels and success criteria. Several were relayed through page or search summaries.
- Only three external items were run by the auditor (section 0). TrellisBMA, DNA-Aeon, StairLoop, Gungnir, Derrick, DNAformer and the harnesses were not run.
- Complexity entries marked "not characterised" or "not extracted" were not found in the audit records; they are not claims of absence.
- VNX-DNA descriptions come from the baseline, which read commit `081697b`. The full test suite at that commit gave 1,690 passed, 3 skipped in a full-suite run on a clean checkout of 081697b (2026-10-05, lab results/full-suite-081697b-20261005-0515.txt). Two V6 native-kernel benchmarks were recorded on a dirty tree and are not used here.
- Licence readings are a research note, not legal advice.
