## 4. Workstream A — Linear-time shuffled-pool stream decoding (P0)
Single partition/index pass over the pool using the existing archive-tag and frame metadata.
1. Inspect exact frame/archive-tag layout first. 2. Parse/validate records once where possible. 3. Partition by unambiguous archive ID/tag. 4. Keep reads' association with original metadata. 5. Decode each extent from its own partition, no rescans. 6. Handle duplicates, malformed, missing extents, reordered, truncated, ambiguous tags, conflicting metadata. 7. Preserve fallback/recovery when records can't be safely classified. 8. Never silently assign an ambiguous record to the wrong extent. 9. Format unchanged unless a proven correctness need. 10. No unbounded index, no unnecessary copies of the whole pool.
Tests: random shuffles; different extent counts; missing/duplicated/corrupted records; ambiguous 16-bit tags; multiple archive IDs and boundaries; empty streams and partial final extents; reference-decoder equivalence; determinism across worker counts.
Benchmark 4 and 16 MiB first, then larger feasible: indexing time, decode time, total wall, peak RSS, scaling with extent count.
Acceptance: partition/index ~O(P + E), decode accounted separately; total pool-decode time no longer grows mainly from per-extent rescans.

## 5. Workstream B — Native pass 2, layout probe, parallel grouping (P0)
1. Profile layout probing, pass-1 prep, grouping, pass 2, verification, output assembly separately. 2. Find duplicated parsing/allocation/conversion/sorting/copies. 3. Native pass-2 kernels only where profiling shows a real bottleneck. 4. Optimize probing / remove repeated work only with proven invariants. 5. Keep Python/reference for differential tests. 9. Preserve fallback ladder and observer-event contracts; document intentional differences.
Per optimization: baseline stage timings -> smallest useful change -> focused + differential tests -> measure independently -> keep only if correct and end-to-end gain reproducible. No 10x claim from a faster component alone.

## 6. Workstream C — Correctness-preserving adaptive recovery scheduler (P0, correctness-sensitive)
Start from the corrected V13 scheduler; never restore the pre-fix one. Investigate safe skips without DP alignment using: indel-robust header validation; marker-anchored projection; strand identifiers and archive metadata; multiple independent corroborating windows; explicit evidence/confidence categories. Implement only skip conditions justified by actual code/format invariants.
1. Observable decisions (counters/diagnostics). 2. Distinguish verified vs unverified/conflicting candidates. 3. A payload-window match alone is never proof of identity. 4. Keep reads too damaged to classify safely. 5. Test structured, zero-heavy, repeated patterns, column parity, noisy headers, indels, RC, dropout, substitutions, duplicates, neighbouring strands. 6. Compare outputs and recovery records with the reference. 7. Keep a diagnostic mode that attempts every eligible read. 8. Record skip reasons, attempted reads, alignment counts, fallback activations. 9. CRC = error detection, not identity proof, not a substitute for the container integrity check.
Acceptance: no correctness regression, no false successes in the declared campaign, measurable end-to-end gain on preregistered workloads. If not demonstrably safe, keep conservative behaviour and document the cost.

## 7. Workstream D — Streaming volume reliability (P1)
Harden existing vnx.volume/1, no second abstraction. Audit: journal validation + torn writes; mid-file corruption vs incomplete final record; write-back ordering + flush semantics; crash recovery + replay idempotency; LRU cache eviction + memory limits; locking/concurrency; interruption/cancellation; partial writes, missing extents, integrity failures; scrub repair/reporting; path handling + filesystem failures.
1. State actual durability guarantees. 2. Never treat arbitrary journal corruption as a harmless torn tail. 3. Never report success when persisted data fails integrity. 4. Repeated recovery/replay safe. 5. Fault-injection tests: interrupted writes, failed flushes, truncated journals, corrupted records, partial extents, process termination. 6. Reopen + scrub after each recoverable failure. 7. Bounded, observable cache. 8. Volume format unchanged unless a demonstrated defect needs a documented migration.
Acceptance: documented crash-recovery contract backed by repeatable fault-injection tests.
