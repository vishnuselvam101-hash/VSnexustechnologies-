## 2. Pre-declared workloads

The end-to-end operation is `vnxdna.v4.decoder.decode_reads(reads.fastq, out.vnx, DecodeOptions(workers=W))`, exactly as
`experiments/arch/compare.py one --step decode` runs it: FASTQ parsing, validation, orientation, exact and
marker-template alignment paths, inner Reed–Solomon + CRC, duplicate resolution, pending-read consensus, outer
decoding, whole-container SHA-256 verification and the write of the output container. A run counts only when its
outcome is `SUCCESS` and the output container is byte-identical to the input archive (`matches_input`). Nothing is
omitted from the timed region; the Python interpreter start and `import vnxdna` are outside it (as in V11/V12).

**Primary workload (the 10× objective is judged on this):**

| id | input | channel (SIMULATED) | workers | seeds | V12 median (ab-session5) |
|---|---|---|---|---|---|
| `indel-w1` | 4 MiB random file, one archive | substitution 1 %, insertion 0.2 %, deletion 0.2 %, coverage 5 | 1 | 95500–95504 | 8.640 s |
| `indel-w4` | same | same | 4 | 95300–95304 | 2.760 s |

**Secondary workloads** (the complete V12 scenario set, unchanged: `experiments/v13/bench/bench.py` `SCENARIOS`):
`indel-w2`, `indel-w8` (worker scaling), `indel-rc-w4` (reverse complement 50 %), `indel-dropout-w4` (dropout 5 %),
`clean-w4` (coverage 3), `substitution-w4` (2 %), `indel-64k-w1` (small input), `indel-16m-w4` (larger input),
`encode-1m-w1`, `encode-4m-w1`, `encode-4m-w4`.

**Denominator and statistic.** Speedup = V12 seconds ÷ V13 seconds on the same seed, same input bytes, same worker
count, in the V12 paired protocol (`experiments/v12/bench/bench.py` method: inputs generated by the baseline tree,
configuration order reversed on odd seeds, one discarded warm-up per configuration and scenario, process-tree RSS
sampled every 0.5 s, median of the per-seed ratios with the percentile-bootstrap 95 % CI, which at n = 5 is the
min–max range). A tier is reached only when the CI lower bound clears it and the scenario is "faster beyond noise"
against the A/A band (`compare_aa.py`): **Tier 1 ≥ 2×, Tier 2 ≥ 5×, Tier 3 ≥ 10×**, reported separately per workload and
worker count. Component-level ratios are never reported as end-to-end.

## 3. Starting profile at 6bf7749 (indel 4 MiB, seed 95300, 1 worker, SIMULATED)

Single run: 9.08 s wall (pass 1 7.84 s, worker CPU 7.16 s, pass 2 1.03 s, verify 0.01 s); 655,755 reads: 197,219 fast
(exact length), 302,991 sync (aligned), 139,942 pending (aligned, inner code failed), 7 unaligned; 107 consensus
attempts, 0 recovered; peak RSS 104 MiB. Profiles: `py-spy record --native --rate 500` (9,331 samples) and cProfile,
lab files `results/v13/pyspy-w1-indel-6bf7749.txt`, `results/v13/cprof-w1-indel-6bf7749.prof`.

| share of samples | where | kind |
|---|---|---|
| 22.4 % | `align_groups_l16` (libvnx_align.so), the banded DP over the usable reads **and** the reverse-complement retry of every failed read (139,942 reads, 0 adopted on this channel) | native, CPU-bound |
| 7.3 % | `decode_rows_avx2` (libvnx_rs.so) | native |
| 2.7 % + 1.0 % + 0.8 % | FASTQ parsing (`line_bytes`, `vnx_reads_feed`, `read`) in the main process | native, serial |
| 1.8 % | `vnx_or_scan` (orientation) | native |
| ≈ 15 % | pass-1 bookkeeping: per-read view lists (`_process` 329/341), `_try` self time, gathers, `np.fromiter` size generators, `_reads_in_domain`, `np.concatenate` of the reads handed to the aligner (cProfile: `align_usable` self 2.77 s of which ≈ 2.1 s native) | Python/NumPy glue, parallel |
| ≈ 4 % | `nt_to_bytes` (four shift/or passes over (n, 4, B) views) | NumPy, parallel |
| ≈ 12 % | pass 2 (`outer.run` 1.15 s cum.: spill loads, `lexsort`/`argsort` 0.39 s, `resolve_duplicates`, per-symbol dict, outer decode, container write) | mostly serial at w1; parallel bucket consensus at w4 |

Measured floor: the native kernels alone (alignment incl. the retry, RS, parsing, orientation) are ≈ 33 % of the w1
wall, ≈ 3.0 s. With every Python line removed and pass 2 free, the current algorithm would reach ≈ 3× at w1. Reaching
10× therefore requires removing alignment work, not only glue — this is stated here so the result can be judged
against the plan.

## 4. Work plan (hypotheses; each item is measured and equivalence-tested before it stays)

1. **C1 flat pass-1 data path** (glue, ≈ 1 s at w1): `_process` → `_try` → `TemplateAligner.project` →
   `native.align.align_usable` carry `(codes, offsets, lengths)` for the default configuration; no per-read lists,
   size generators or concatenations. Invariant: identical arrays to the list path (pinned tests).
2. **C2 reverse-complement retry on flat buffers**: vectorised reversal/complement of the retried reads. Same
   decisions.
3. **C3 `nt_to_bytes`**: a faster exact form (NumPy or native). Same bytes.
4. **E1 pass 2**: fewer passes over the accepted records (single sort, no per-symbol dict until needed). Same symbols,
   same conflicts, same order.
5. **D1 adaptive orientation retry (opt-in strategy)**: skip the reverse-complement retry for reads whose orientation
   evidence from the pre-pass is decisive. This changes decisions in principle (the retry can adopt an RC alignment of
   lower cost), so it ships **disabled by default**, with its own equivalence corpus and the strategy recorded in the
   report; it is benchmarked separately and never counted in the default-path tier.
6. **B1 marker-anchored speculative projection** (only if 1–4 land): a cheap projection from per-block marker shifts,
   accepted only when the inner RS + CRC verify, else the DP runs unchanged (the same verification-gated pattern as the
   exact-length fast path). Acceptances can only be added, never removed.
7. **H V13 benchmark suite** `experiments/v13/bench/` = the V12 harness with labels `v12`/`v13` and `BASE_TREE` =
   `/root/vnx-dna-lab/v13-base`; A/A run of the baseline against itself for the noise band of this session.

Memory gate: peak process-tree RSS of V13 within 10 % of V12 on every decode scenario (V12's chunked gathers, bucket
transients and `trim_heap` stay). Correctness gate: identical output and outcome on every seed, 0 false successes,
full suite ≥ 4,209 passed with 0 failures, sanitizers and differential fuzz for any native change, V4/V5/V6 golden
archives decoding.
