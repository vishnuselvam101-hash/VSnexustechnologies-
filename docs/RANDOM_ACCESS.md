# Random access

```bash
vnx-dna extract archive.vxdna --offset 500000000 --length 1048576 --output section.bin   # from a container
vnx-dna extract strands.vxs   --offset 500000000 --length 1048576 --output section.bin   # from DNA (uses strands.vxs.vxidx)
vnx-dna extract archive.vxdna --chunk 42 --output chunk42.bin                             # one whole chunk
```

## How it works

Every chunk is compressed, encrypted and ECC-protected independently. Its location is recorded twice:

* in the **container**, the authenticated chunk index gives the byte offset and size of each stored chunk. `extract`
  reads only the chunks that overlap `[offset, offset + length)` with `pread`, verifies each chunk's stored SHA-256,
  AES-GCM tag and plaintext SHA-256, and writes the requested slice;
* in the **DNA**, each chunk occupies whole ECC groups, and the **DNA index** (`<strands>.vxidx`, written by `encode`)
  records where each chunk's strands are in the strand file (record range for VXS, byte range for FASTA), plus the
  metadata strands' range. `extract` reads the metadata strands (to rebuild and authenticate the manifest), then
  **only the needed chunks' strands**, decodes only their ECC groups, and verifies them.

Without a DNA index (for example on sequenced reads, whose order has nothing to do with the archive), `extract`
must scan every read. It still assembles and decodes only the needed chunks. The report says which path was used
(`dna_index`), and gives `chunks_processed`, `strands_processed`, `container_bytes_read` and the runtime.

## Limitations

* **Not molecular random access.** A physical system would select strands by PCR with chunk-specific primers.
  VNX-DNA assigns no primers. With a DNA index it reads only the needed records of a strand *file*, which is the
  software equivalent. On an unordered read set it must parse every read.
* **Granularity is one chunk** (1 MiB in the balanced profile). A 1-byte request decodes one chunk; a range crossing
  a boundary decodes two.
* **The manifest is always needed** (from the container, or from the metadata strands, which must be present).
* **The DNA index is tied to one exact strand file** (size and SHA-256 recorded). A different or modified file is
  detected by size and falls back to a full scan. Correctness never depends on the index: every chunk is checked
  against the authenticated chunk index.
